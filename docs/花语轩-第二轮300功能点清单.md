## 全局红线（施工时必须遵守，验收也按这几条查）

- **不依赖 Redis**：需要跨请求计数一律用 Caffeine 本地缓存（`CacheConfig` / `TokenBucketRateLimiter` 现成），
  或落库 + 条件 UPDATE；多实例扩容问题本轮不解决，口径写进条目说明即可。
- **不新增 Maven 依赖**：现有可用 = web / thymeleaf / data-jpa / validation / security-crypto / flyway /
  cache+caffeine / actuator / springdoc / hutool-all / jbcrypt / java-jwt / postgresql。
  图片合成用 JDK `Graphics2D`，TOTP 用 JDK `HmacSHA1`，PDF 一律不做（改用打印页）。
- **不引入外网 CDN 或联网资源**：字体、图标、模型、地图 JS、天气全部本地/已自托管；
  高德只用现成的 `map_web_key`（前端注入）与 `AmapClient`（服务端代理），**任何接口、页面、日志、导出都不回显高德 key 与 password**。
- **并发口径**：库存/余额/额度/名额一律「条件 UPDATE + 影响行数断言」（照 `ProductRepository.decreaseStock` 的写法），
  0 行即回滚并返回可读原因；`@Modifying(clearAutomatically = true, flushAutomatically = true)` 之后
  **不得再访问懒加载关联**（要么提前取，要么重查 repository）；退款/回补/发券一律 CAS 只允许一次。
- **迁移纪律**：`V1–V34` 已执行，**绝不可原地改**（第一轮已因此踩过 checksum 事故）；新迁移一律 `V35+` 顺号、
  全部 `IF NOT EXISTS` / `WHERE NOT EXISTS` 写成可重放；`V26/V27` 是历史缺号，不要占用；
  落库前用 `tools/PgExec.java check` 事务内干跑再回滚。
- **验收口径**：每条要么有接口参数/服务端校验的实测响应，要么有后台列/页面截图，要么有单测类名；
  只写「已优化」不算完成。

## 建议实施顺序

| 顺位 | 组 | 理由 |
|---|---|---|
| 1 | **U 消息通知中心与客服工单** | M/N/Q/P 的到期提醒、成团结果、派单异常、订阅通知都要出口；先做 U 可让后续组只接事件不再造轮子 |
| 2 | **V 供应链、批次效期与毛利** | `StockService` 收敛（V09）是所有新增扣减（Q 活动、N 订阅、R 套餐、P BOM）的地基，越晚改越贵；同时给 X 组毛利与 W 组对账提供数据 |
| 3 | **Q 拼团 / 砍价 / 秒杀与营销风控 + X19–X23 RBAC/审批** | Q 的 `stock_hold` 两段式与风控口径复用到 M/N/O；X 的权限与双人复核必须在资金类功能（M/O）大规模接入前落地，否则资损无护栏 |

> 其余组可并行穿插：M/N/O 属资金与现金流，必须在 X19–X23 落地后才允许对真实用户放量；
> T/S/R 属体验层，依赖 W15–W18 的特性开关做灰度，不阻塞主链路。
