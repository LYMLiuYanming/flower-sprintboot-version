## 1. 系统概述

花语轩是一个单体（Monolith）鲜花电商系统，包含**前台商城**（面向消费者）与**后台管理**（面向运营人员）两部分，采用服务端渲染（Thymeleaf）+ AJAX JSON API 混合模式：

- **前台**：首页、商品浏览/搜索、商品详情、购物车、下单结算、订单管理、个人中心、登录/注册
- **后台**：数据看板、商品/分类/订单/用户/轮播图/公告七大管理模块（Layui 表格 + REST API）

### 3.3 鉴权与会话模型

- **会话（HttpSession）+ 自定义拦截器**，非 Spring Security 过滤链
- `AuthInterceptor`：拦截需登录路径；未登录时页面 302 → `/auth/login?redirect=…`，API 返回 JSON `{code:401}`
- 角色：`userType = admin | customer`，后台路径校验 admin
- 会话固定防护：登录成功后 `request.changeSessionId()`；`server.servlet.session.tracking-modes=cookie` 禁止 URL 重写回写 sessionId
- Cookie：`FLOWERSESSIONID` + HttpOnly + SameSite=Lax，空闲 30 分钟失效
- 记住我：`RememberMeService` 签发 HMAC-SHA256 签名 Cookie（含密码指纹），改密/退出即作废；密钥 `app.remember-me.secret`（生产由 `FLOWER_REMEMBER_SECRET` 注入）
- 登录防暴力：`LoginAttemptService` 按 IP+用户名累计失败并锁定，配合 `CaptchaService` 图形验证码
- 密码：BCrypt 哈希存储；`migratePlainPasswords()` 启动时将存量明文平滑升级
- 全局模型注入：`GlobalModelAdvice` 向所有 Thymeleaf 模板注入登录态（header 片段据此渲染用户名/登录按钮）

### 5.3 API 约定

- 统一响应体 `Result{code,msg,data,count}`；code：200 成功 / 401 未登录 / 403 / 404 / 500
- **HTTP 状态恒为 200，业务结果看 body.code**（含 `/api/**` 未匹配路径由 `ErrorPageController` 兜底为 `{code:404,msg:"接口不存在"}`）
- 入参一律 `@RequestBody` JSON + record DTO + `@Valid`；出参为 `vo/*View`，实体不直接序列化（`UserView` 无 password）
- 金额/库存/折扣/积分只在服务端重算（`PointsPolicy`），前端展示口径与其对齐
- Layui 表格数据接口需返回 `count` 供分页；`admin-common.js` 已把 Layui 默认 `code:0` 改为 `code:200`

  结算页把 `datetime-local` 换成「日期胶囊 + 时段网格」两级日历，每格显示「剩 N / 约满 / 已截止」；
